# ERP UI 设计规范

本规范适用于 `erp-vue/src` 的登录页、应用壳、业务页和嵌入业务详情的附件面板。前端继续使用 Vue 3、JavaScript、Vue Router、Element Plus、现有图标库和 `lib/api.js` 的 fetch 封装。没有新增依赖，也没有改变后端响应、权限、数据范围或业务状态规则。

## 页面清单与审查结论

实际路由包括运营概览、综合查询、七类业务报表、站内通知；产品、分类、品牌、单位、仓库；库存查询、流水、期初、入库、出库、领用、盘点；设备、维修、保修、换货、二维码标签；用户、部门、角色、权限和系统入口；登录、403、404。主要重复问题是旧侧栏把所有业务平铺、页面标题使用两套结构、表格列宽和状态色不统一、筛选区与操作按钮混在一起、复杂详情缺乏分区。

## 基础 Token

Token 定义在 `src/assets/base.css`，组件级布局在 `src/assets/main.css`。页面局部样式只处理本页面特有的结构。

| 用途 | Token | 值 |
| --- | --- | --- |
| 品牌操作色 | `--brand` | `#145bff` |
| 强调文字 | `--brand-dark` | `#104bd4` |
| 主背景 | `--canvas` | `#f5f7fb` |
| 内容面 | `--surface` | `#fff` |
| 细边框 | `--line` | `#e4eaf2` |
| 主文字 | `--text` | `#18243a` |
| 次文字 | `--text-secondary` | `#59677c` |
| 辅助文字 | `--text-muted` | `#78869a` |
| 圆角 | `--radius` | `10px` |

字体沿用系统无衬线字体。常规正文为 13px，页标题 24px，小节标题 15～17px，表头和辅助信息 11～12px。按钮及输入框沿用 Element Plus 的键盘焦点反馈。动效仅用于导航收折和组件自身状态，并尊重 `prefers-reduced-motion`。

## 应用壳和导航

`AppLayout.vue` 用静态路由定义和现有 `hasPermission` 过滤菜单，分为工作台、基础资料、仓储业务、设备业务、分析报表、系统管理。空权限分组不出现。桌面侧栏宽 248px，可折叠到 72px；窄窗口改为覆盖式侧栏，页面仍可纵向滚动。品牌区与顶栏高 66px；导航维持单层折叠分组和原有 Logo。导航点击、顶栏综合查询、通知未读数和用户退出均接入真实路由或 API。顶部展示当前分组和页面；不存在的全局功能不显示。

## 仪表盘

`DashboardView.vue` 只使用 `GET /api/dashboard/summary` 的 `metrics`、`deviceStatuses`、`recent`。待办和库存风险仅列出非零项；业务规模显示实际可见的物资、仓库、设备和库存位置计数。设备状态条由状态数除以当前可见设备总数，数据为零时不画条。近期记录保留真实类型、状态、时间和业务入口。不同单位的 `stockQuantity` 不作为可比较的总量展示。

第二轮精修后，上方待办与快捷入口按内容高度排列，不再互相拉伸；快捷入口在宽屏为三列、较窄桌面为两列，小屏在待办下方换行。待办为零时使用一行轻量提示；接口缺少可用指标时显示权限或数据不可用提示，不把缺失值当成零。基础指标采用薄边框的响应式网格，展示名称、真实数值、口径提示和跳转方向；真实零值显示 `0`，无效值显示 `—`。近期动态有记录时使用原有真实字段表格，无记录时使用紧凑文本空状态。加载中显示骨架，失败时显示错误和重试入口。

常规桌面主内容内边距为上 22px、左右 28px、下 36px；页面标题与内容间隔 16px，仪表盘分区间隔 14px。通用卡片正文内边距 18px，筛选区 13px，表格表头 42px、数据行上下 7px，分页顶部间距 14px。这些值用于压缩无效空白，不作为所有业务页必须同高的约束。

## 列表、筛选与分页

- 标题说明业务目的，主操作置于标题右侧；查询为主要按钮，重置为次要按钮。
- 筛选区使用浅色面板。报表保留常用条件，ID、产品类型、保修等条件放入可展开的高级筛选；生效项数可见。原筛选参数、分页、Excel 导出与 50,000 行限制保持原样。
- 表格采用浅表头、细边框、约 42px 表头高度、稳定的行内操作间距。关键编码和名称优先；数量右对齐，长编号提供溢出提示，状态同时使用文字与颜色。横向列过多的设备、单据和报表表格在表格内滚动，操作列固定在右侧。
- 分页继续由后端处理；空结果、请求错误和加载反馈分别显示。表格数据不得替换为浏览器假数据。
- `lib/status.js` 仅映射状态颜色。状态名称和允许的动作仍由现有页面及后端决定。

## 表单、详情和反馈

弹窗最大宽度与高度受视口约束，正文独立滚动，页脚始终保留取消和确认操作。物资与设备详情按归属、标识和时间分区；维修、保修、换货使用同一结构，但换货原设备和新设备独立呈现。附件面板保留业务权限控制，显示上传限制、操作中状态、对象状态与失败信息。通知列表展示未读标识、摘要、时间和原有业务跳转。请求失败信息追加后端 `X-Request-Id`，便于和日志关联。

二维码页面只调整屏幕布局和帮助文案；打印区的 `--label-width`、`--label-height`、`--qr-size`、`--label-margin`、ERPQR1 内容和 `@media print` 规则继续保留。

## 维护边界

本轮没有图表库、第二套组件库或新状态管理库。业务页后续增加字段时应优先沿用上述标题、筛选、表格、表单和状态语义。库存、单据、设备状态流转、审批确认和数据范围仍以已有后端规则为准。

## 第三轮业务页精修

`--control-height` 和 `--table-row-padding` 统一控件最小高度与表格行内边距。业务列表共用 `business-filters`、`filter-actions`、`result-heading`，区分筛选条件、主要查询动作和结果数量。产品、设备、维修类及报表的低频条件可展开；条件仍作为原参数传给后端。结果加载、空结果和请求失败分别呈现，失败时不保留上一轮结果冒充当前查询。

`record-code`、`record-name`、`number-cell`、`change-value` 提高编号、名称和数值的可扫读性；出入库变化同时保留正负号或业务文字，不只靠颜色。表格操作列尽量固定在右侧，数量列右对齐，长编号提供溢出提示。报表七类共用筛选与结果样式，统计仍来自后端。单据和详情的 `dialog-section-title`、`detail-lead` 用于区分基本信息、明细及状态；长表单正文滚动，页脚留在可见区域。附件大小按 B、KiB、MiB 显示，上传进度只显示真实操作中状态。通知查看和报表导出在请求中禁用重复操作。

首页布局、品牌、导航宽度和权限入口沿用第二轮结果。二维码标签的编码、打印尺寸和打印样式未改。本轮未引入任何依赖，未调整后端接口、权限判断、数据库或单 JAR 资源整合。
